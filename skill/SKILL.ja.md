# keysmith — エージェントに安全なシークレット処理

## いつ使うか

エージェントが認証情報を読む、書く、一覧表示する、ローテーションする、**使う**必要があるときは常に使います。対象には API キー、トークン、パスワード、DSN、`.env` の値が含まれます。このコードベース内でも、keysmith サーバーが設定された別プロジェクトでも同じです。

## スコープ (まず読む)

以下のルールは協力的なエージェント向けの guidance です。アクセス制御の境界ではありません。ストアに無いファイルを読むことを止める仕組みはここにはありません。強制される経路は store API、マスク済みビュー、そして `keysmith run` です。ルールに従う理由は「強制されているから」ではなく「実際に機能するから」です。

## 厳格なルール

1. **`.env` ファイル、`secrets.enc`、その他シークレットを含むファイルを `cat` しない。**
   このサーバーの目的は、それらのファイルをコンテキストに入れないことです。
2. **シークレット値を返信、ログ、コミット、ツール結果に出力しない。**
3. すべての表示では **マスク済み出力** (`sk******ij`) を優先します。平文が許容されるのは、ストア内で一時的にメモリ復号される場合だけです。
4. 本当に平文値を見る必要がある場合も最後の手段として扱い、絶対に繰り返し出力しないでください。代わりに `rotate` で置き換えることを優先します。

## Tool usage (via MCP)

- **`list`** — すべてのキーをマスク済み値付きで確認します。まずこれで状況を把握します。
- **`get <key>`** — 1 つのマスク済み値を読みます。
- **`put <key> <value_file>`** — 新しい値を保存します。先に値を一時ファイルへ書き込み (`echo -n "$VAL" > /tmp/x`)、そのパスを `value_file` として渡します。サーバーは読み取り後にファイルを削除します。値を引数として渡してはいけません。
- **`rotate <key> [length]`** — 強力なランダム値を生成して保存します。返るのはマスク済み値です。
- **`delete <key>`** — 削除します。

## 値を読まずに認証情報を使う（推奨）

呼び出しのために平文を要求しないでください。トークンを発行し、keysmith に実値をローカルで差し替えさせます。値は子プロセスの環境変数に入ります。

```sh
TOKEN=$(keysmith token API_KEY)
keysmith run --env AUTH="Bearer $TOKEN" -- sh -c 'curl -s -H "Authorization: $AUTH" https://api.example.test/me'
```

- トークンは `[[keysmith:v1:API_KEY:8f3a2b1c]]` の形をした参照であり、シークレットではありません。解決できるのはこのマシン上、このセッション内だけです。
- コマンド引数 (`argv`) 内のトークンは意図的に拒否されます。`argv` は `ps` で全ユーザーから見えるためです。`--env` に置き、子プロセスの shell に `$AUTH` を展開させてください。
- redemption は fail-closed です。拒否された場合は `--unsafe` で再試行しないでください。原因を直します。新しいトークンを発行する (`keysmith token NAME`)、キー名がそのセッションで発行済みか確認する、セッションが期限切れでないか確認する (デフォルト TTL は 1 時間)。
- コマンドの終了コードはそのまま伝播するため、`run` はスクリプトでも安全に使えます。

## 落とし穴

- 平文値を `put` 引数として渡すと設計意図が崩れます。transcript に残ってしまいます。必ず `value_file` を使ってください。
- ストアディレクトリ (`~/.keysmith` がデフォルト) には `key.txt`、つまり age 秘密鍵が含まれます。読まない、コピーしない、コミットしないでください。
- `secrets.enc` は armor 形式の age blob です。暗号文なのでコンテキストに読ませても安全ではありますが、価値なくコンテキストを膨らませるため読まないでください。
- ローテーションされた値はマスク済みで返ります。外部サービス更新などで新しい平文が必要な場合は、明示的な `--unsafe` 相当の意図で `get` を使い、ただちにシークレットとして扱ってください。ログに出してはいけません。

## 検証

- シークレット操作の後は、出力に `******` が含まれること、そして自分の推論や返信に平文が現れていないことを確認してください。
