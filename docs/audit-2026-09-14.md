# Audit — 2026-09-14

Scope: can an AI agent obtain a plaintext secret from keysmith's MCP layer, and
what does the answer imply for the redemption layer added the same day?

Reproduce:

```sh
go build -o bin/keysmith ./cmd/keysmith
python3 scripts/probe-mcp-plaintext.py   # MCP vs CLI plaintext probe
python3 verify_redeem.py                 # redemption fail-closed checks
```

Everything below is captured output, not a summary. Synthetic values only
(`sk-synthetic-CANARY-0001`); no real credential was used or printed.

## 1. The agent path has no plaintext route

```text
[MCP] tools exposed to an agent:
  - delete   params=['key']
  - get      params=['key']
  - list     params=[]
  - put      params=['key', 'value_file']
  - rotate   params=['key', 'length']

[MCP] attempts to reach plaintext:
  get      args={"key": "DEMO_KEY"}                -> sk******01
  get      args={"key": "DEMO_KEY", "unsafe": true} -> validating "arguments": validating root: unexpected additional properties ["unsafe"]
  get      args={"key": "DEMO_KEY", "--unsafe": true} -> validating "arguments": validating root: unexpected additional properties ["--unsafe"]
  list     args={}                                 -> DEMO_KEY=sk******01
  list     args={"unsafe": true}                   -> validating "arguments": validating root: unexpected additional properties ["unsafe"]

[MCP] resources/read secret://secrets -> DEMO_KEY=sk******01

[CLI] get DEMO_KEY --unsafe -> plaintext returned: True
[disk] secrets.enc contains the canary: False

=== RESULT: MCP plaintext leaks = 0 (none)
=== RESULT: plaintext reachable only outside MCP: True
```

Observations:

1. **No tool result or resource leaks a value.** Masking holds on every path an
   agent can reach, and `secrets.enc` contains no plaintext.
2. **Plaintext is reachable only through the CLI** (`get --unsafe`), i.e. by the
   human who owns the store — not by the agent.
3. **The tool descriptions advertised an escape hatch that does not exist.** The
   `get` and `rotate` descriptions told the agent to "use `--unsafe`", but the
   MCP schemas have no such parameter: an agent that follows the advice gets a
   protocol-level validation error and burns a turn. Fixed in `904b78e`.
4. **Detection is best-effort.** The masked form keeps the first and last two
   characters (`sk******01`), a deliberate small disclosure so credentials stay
   distinguishable. Documented in the README boundaries section.

This is the shape of the gap the redemption layer fills: over MCP a value is
readable-but-unusable, and the only way to use one was `--unsafe`, which puts
plaintext into the transcript. `keysmith run` (see `docs/REDEEM.md`) makes the
value usable without ever handing it to the agent.

## 2. Redemption, verified from outside the process

`verify_redeem.py` starts real children and inspects them:

```text
[2] happy path — the child gets the real value, argv stays clean
  PASS child environment carries the real value
  PASS value is absent from the child's argv
  PASS token is absent from the child's argv
  PASS session id is not exported to the child

[3] token in argv is refused
  PASS token in argv refused (non-zero exit)
  PASS token in argv refused: no child started
  PASS refusal leaks no value

[4] fail-closed resolution
  PASS unknown session: refused, no child, no value
  PASS name not issued in the session: refused, no child, no value
  PASS malformed token: refused, no child, no value
  PASS truncated reserved prefix: refused, no child, no value
  PASS expired session: refused, no child

[5] exit code propagation and audit log
  PASS child exit code is propagated
  PASS audit log records the key name
  PASS audit log contains no value
```

Evidence method: `/proc/<child pid>/environ` and `/proc/<pid>/cmdline` of the
live child, read by the test process. The value is present in the environment and
absent from `argv`. `sk******01`-style masking and `--unsafe` are unchanged.

## 3. What this audit does not claim

- It does not test a *malicious* agent that reads files directly (`cat .env`
  still works — keysmith narrows paths, it does not close them).
- It does not test same-UID isolation: a process running as the same user can
  read `key.txt` and decrypt the store. Out of scope, see `docs/THREAT-MODEL.md`.
- It does not test network egress: nothing here stops a process from posting a
  value it obtained elsewhere to an arbitrary host.
- One synthetic fixture, one platform (Linux, Go 1.25). No coverage of the
  Vault backend or of SSE/Streamable transports.
